# FPGA Workbench 后续开发指南

记录日期：2026-11-10。
分析基线：0.2.21 本地预发布源码。
文档状态：开发方向与验收要求。
本指南不表示所列功能已经实现。
每个阶段应另行确定范围后开发。

## 产品方向

从现有 Vivado XPR 工程出发，帮助阅读代码。
重点解决模块定位、信号引用和实际端口连接。
先提高工程检查的可靠性，再增强编辑辅助。
保持现有 Ctrl 加鼠标左键的主要操作。
源码、工程配置和工具配置应有明确边界。

着色、固定模块标题和缩略图标题属于基础体验。
这些功能应保持稳定，避免反复改变日常操作。
语法颜色默认跟随当前主题。
插件固定配色只作为可选模式。
完整仿真、波形、综合、实现和下载暂不作为主线。

## 0.2.21 基线与缺口

| 领域 | 当前能力 | 后续缺口 |
|---|---|---|
| 工程入口 | 读取 XPR 文件集、宏、include 和顶层 | 统一各功能消费的工程信息 |
| 导航 | Verilog/SV 模块、定义、引用和上一层连接 | 悬停、实例上下文和 VHDL 导航 |
| 检查 | 工程或文件编译检查，支持 VHDL | 按当前语言选择范围，完善依赖和失败归因 |
| 导出 | 独立 Filelist Skill，包含 IP 路径注释 | 补齐 VHDL、逻辑库和语言标准 |
| 编辑 | 着色、括号层级、固定标题和代码片段 | 补全、实例生成、重命名和格式化 |
| 性能 | 取消旧任务，隔离检查产物 | 记录大工程基线，减少重复解析 |

0.2.21 的 Lint 已读取 VHDL 及逻辑库信息。
导航和 filelist 仍使用 Verilog/SV 源文件范围。
因此，不能把三者视为相同的完整工程清单。
XPR 静态文件顺序也不等于实际编译顺序。
编译成功不能证明功能、CDC 或时序正确。

## 检查范围要求

以下是 2026-11-10 补充的目标行为。
实现状态以版本说明和检查记录为准。

| 触发场景 | 目标检查范围 | 工具要求 |
|---|---|---|
| 当前工程文件为 `.v` 或 `.sv` | 工程中的 Verilog/SV 编译单元及头文件依赖 | 不因其他 VHDL 文件启动 xvhdl |
| 当前工程文件为 `.vh` 或 `.svh` | 工程中的 Verilog/SV 编译单元 | 头文件不单独作为编译单元 |
| 当前工程文件为 `.vhd` 或 `.vhdl` | 工程中的 VHDL 编译单元 | 使用 xvhdl 或 vcom，保留逻辑库与语言标准 |
| 没有有效的当前工程源码 | 保留整个 XPR 的检查入口 | 明确实际范围和各语言检查状态 |
| 保存工程外的 HDL 文件 | 检查该文件 | 使用该文件所属语言的工具 |

范围筛选必须先于工具选择。
Verilog 检查不应因工程含 VHDL 而阻断。
检查输出必须说明本次包含和排除的语言。
部分语言检查不能显示为整个工程通过。
环境错误应显示为工程或工具问题。
不得把这类错误归到无关 Verilog 文件的第 1 行。
真实源码诊断仍应保留文件、行列和诊断来源。

## 开发优先级

以下项目均为计划项。
优先级表示实施顺序，不表示已承诺的版本或日期。

| 优先级 | 方向 | 主要交付 |
|---|---|---|
| P0 | 统一工程元数据 | 文件、文件集、启用状态、语言、库和标准 |
| P0 | 混合语言导出 | VHDL 路径、库和标准，明确静态清单语义 |
| P0 | 检查依赖与诊断 | 范围、编译顺序、缺库原因和工具状态 |
| P1 | 信号悬停 | 声明、方向、位宽、参数和实际连接 |
| P1 | 实例上下文 | 候选列表中的实例路径和连接位置 |
| P2 | 增量刷新 | 减少重复解析，避免不必要的服务重启 |
| P2 | 编辑辅助 | 端口补全、参数补全和实例生成 |
| P3 | VHDL 导航 | 对应语言的定义、引用和层级 |
| P3 | 局部连接图 | 当前模块附近的端口连接与跳转 |

### P0 验收要求

- 各功能共享基础工程元数据。
- 各工具按能力生成输入，不强制统一语言范围。
- 导出保留 VHDL 路径、逻辑库和语言标准。
- 明确区分静态清单与可用于编译的有序清单。
- 检查覆盖包依赖、多库、禁用文件和缺失文件。
- 区分源码错误、缺库、缺文件和工具启动失败。
- 显示编译器路径、版本和实际检查范围。
- 检查未完成时显示原因，不显示为通过。
- 环境问题不产生无关源码位置。

### P1 验收要求

- 悬停显示端口方向、声明和位宽表达式。
- 已解析的位宽与源码表达式分别显示。
- 参数化模块显示当前实例的参数值。
- 无法确定的值明确标记，不显示猜测值。
- 同一模块的多个实例使用实例路径区分。
- 候选列表保留完整端口连接。
- 保持本模块引用和上一层连接的范围规则。

### P2 验收要求

- 未变化的文本不重复解析。
- 普通文件保存尽量不重建整个工程索引。
- 连续编辑和切换工程不产生旧诊断。
- 准备 100 文件和 1000 文件的性能样例。
- 记录冷启动、保存后恢复导航的时间和内存。
- 记录定义查询和引用查询的延迟。
- 先测量基线，再确定性能目标。
- 补全覆盖端口名、参数名和 package 成员。
- 实例生成提供预览，保留已有端口连接。

### P3 验收要求

- VHDL 导航与现有 Verilog/SV 导航分别检查。
- 混合语言连接只显示能够确定的关系。
- 局部连接图支持返回源码。
- 图中标明未解析的模块、端口或表达式。
- 不把局部静态关系描述为完整数据流分析。

## 暂缓方向

完整仿真管理、波形查看和 FPGA 构建暂缓。
这些方向会增加工具版本、库和运行环境的适配。
需要时可先联动成熟工具，再决定是否内置。
重命名和格式化也应单独确定范围。
格式化必须保持源文件编码，提供差异预览。
